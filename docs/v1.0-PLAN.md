## 1. Scope Decision

**Position: v1.0 is an API-freeze + stability release, not a feature release.**

Rationale:
- The four features the previous v1.0 plan gated on (row expansion, grouping/aggregation, server-side mode, accessibility) all shipped between v0.1.18 and v0.2.0. v0.2.5 added the last missing primitive (column groups) plus row drag-and-drop, clipboard copy, and a minimal CSS tier.
- What the library lacks for v1.0 is not more features — it is the SemVer commitment, quality gates, doc truth, and a clean migration story.
- Shipping more net-new features in v1.0 would re-open surface area the moment we need to freeze it. Feature work is deferred to v1.1+.

### Breaking vs. preserved

v1.0 intentionally makes very few breaking changes. Every item below is in scope only if the cleanup is load-bearing for long-term SemVer:

| Item | Breaking? | Decision | Location |
|---|---|---|---|
| Three component aliases `Table` / `IoiTable` / `DataTable` | No | Keep all three. `Table` remains primary; `IoiTable` and `DataTable` stay as re-exports. Add `@deprecated` JSDoc on `DataTable` only — removal scheduled for v2.0. | `src/index.ts`, `src/unstyled.ts` |
| CSS path aliases `style.css` + `styles.css` | No | Keep both. Canonical is `styles.css`. Document both in API-REFERENCE. | `packages/vue-table/package.json` exports |
| `data-mode="server"` + `:server-options` | No | Already canonical. Audit docs for any lingering `:fetch-fn` references. | `README.md`, `API-REFERENCE.md` |
| `serverOptions.query` vs `fetch` | No | `query` is correct (see `src/types.ts:533`). Docs that say `fetch:` (API-REFERENCE, AI.md, MIGRATION, READMEs) are wrong — fix as part of v1.0 doc pass. | `src/types.ts` |
| Event payload `schemaVersion: 1` | **Frozen at 1 for all v1.x** | Documented commitment. | `src/types.ts`, `MIGRATION.md` |
| `expandedRowKeys` as `Array` vs `Set` | No | Keep Array for JSON-serializable controlled state. | `src/types.ts` |
| TypeScript peer range | Internal | Document `>=5.3 <5.10`. The `ignoreDeprecations` tsconfig workaround was removed in v0.2.5 — keep removed. | `packages/vue-table/tsconfig*.json` |
| Drop `DataTable` alias | **Yes — deferred to v2.0** | Do NOT drop in v1.0. | — |

No v0.2.x prop/event/slot is renamed in v1.0.

## 4. Release Mechanics

### Branch / version
- Branch `release/v1.0.0` cut from `release/v0.2.5` tip after v0.2.5 is tagged.
- `packages/vue-table/package.json` version bumped `0.2.5` → `1.0.0` **only** in the final release commit. `package-lock.json` regenerated in the same commit.
- RC path: `1.0.0-rc.1` → `rc.2` → `1.0.0`. RC tags published with `npm publish --tag next`.

### CHANGELOG entry (top of `packages/vue-table/CHANGELOG.md`)
- New `## 1.0.0` section. Categories: **API Freeze**, **SemVer Commitments**, **Quality Gates**, **Docs**, **Internal**. Explicitly state "no breaking changes from 0.2.5".

### MIGRATION.md
- Prepend `## v0.2.5 → v1.0`. Subsections: Breaking changes (none), SemVer guarantees, event `schemaVersion: 1` frozen, stability tiers, deprecations scheduled for v2 (`DataTable` alias), keyboard shortcut reference.

### README / ROADMAP
- Root `README.md` — version badge to 1.0.0, "Stable v1.0" callout.
- `docs/ROADMAP.md` — v1.0 marked Released + date; v1.1 targets Q3 (WASM); v1.2 targets Q4 (MCP, nested column groups, RTL); keep "Out of Scope" list intact.

### npm publish flow
1. `npm run build --workspace @ioi-dev/vue-table` (vite build + `vue-tsc --declaration --emitDeclarationOnly` + `dist/minimal.css` copy).
2. `npm run verify:artifact --workspace @ioi-dev/vue-table`.
3. `npm publish --access public` from `packages/vue-table/`. `prepack` runs `build + verify:artifact` automatically.
4. After publish: `git tag v1.0.0`, `git push origin v1.0.0 release/v1.0.0`.

### CI signals required before tagging 1.0.0
test · test:coverage · typecheck (matrix) · lint · build · verify:artifact · bundle-size · a11y · SSR · public-API snapshot · `npm pack --dry-run` audit. Benchmark comment posted on PR (non-blocking).

## 5. Deferrals

### v1.1 (2026-Q3) — WASM Performance Layer
- Rust path resolver, virtual engine, sort/filter, CSV streaming.
- Horizontal virtualization (architectural prerequisite for many v1.2 items).
- Column auto-sizing to fit content.
- Dark-mode prop (moved down from old v1.0 nice-to-have).

### v1.2 (2026-Q4) — Advanced + MCP
- **MCP server bridge**: `useMcpBridge` composable + `@ioi-dev/vue-table-mcp` package. Read-oriented tools. Permission model. Explicitly v1.2 per project memory — NOT v1.0 or v1.1.
- Nested column groups (v0.2.5 ships single-level only).
- RTL support.
- Router sync + persistence adapters.
- Column menu, frozen columns, undo/redo, bulk edit, custom cell editors.

### v2.0+ — Long-horizon
- Drop `DataTable` alias (SemVer major).
- Multi-table MCP coordination, write-mode permissions, audit guardrails.
- Vapor mode.

Explicitly out of scope (per `docs/SPEC.md`): pivoting, spreadsheet formulas, built-in charts, PDF export, print optimisation, advanced mobile gestures.
