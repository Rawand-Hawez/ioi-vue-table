# v0.3.0 Fresh-Install and Design-System Integration Implementation Plan

> **For Claude:** Use superpowers:executing-plans if that skill is installed.
> If it is not available in the session, execute this plan manually,
> task-by-task and in order, keeping the same discipline: write the failing
> test first, implement, run the task's verification commands, and commit with
> the task's commit message before starting the next task.

**Goal:** Ship v0.3.0 with a reliable fresh-install experience, complete default styling, visible pagination, default sorting, truthful component contracts, and an official Tailwind/shadcn integration path.

**Architecture:** Keep `useIoiTable` as the state engine and `IoiTable.vue` as the rendering boundary. Add complete CSS themes and typed component slots rather than coupling runtime code to Tailwind or shadcn. Treat packed-consumer verification as a first-class test boundary so package exports, CSS, documentation, and generated declarations are validated together.

**Tech Stack:** Vue 3, TypeScript, Vite library mode, Vitest, Vue Test Utils, npm workspaces, Tailwind CSS 4 playground, shadcn-compatible CSS variables.

---

## Release Principles

- Preserve the existing package name and primary `Table` export.
- Keep changes additive wherever possible because v0.3.0 is a minor release.
- Use one canonical name for every prop, event, slot, and server callback.
- Make the default path functional without consumer-written controls.
- Do not bundle or imitate shadcn components inside the library.
- Make AI guidance inspect and reuse the consumer's existing UI system.
- Write failing tests before each behavior change.

## Definition of Done

- The documented default install renders a complete neutral table.
- The first row has no focused background before actual interaction.
- Default headers sort without custom playground code.
- Positive `pageSize` produces usable pagination controls.
- Pagination can be fully replaced with shadcn controls through a typed slot.
- Selection and editing examples compile and behave as documented.
- Server examples and runtime use the same callback name.

  URLs linked from the npm README.
